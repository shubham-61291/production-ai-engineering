# 🧲 Magnetar EXE Builder

**AI-Powered Windows Application Generator with ReAct Agent, Open-Source LLM, and GitHub Actions**

---

## 📖 Overview

Magnetar EXE Builder is a production-grade platform that converts natural language requirements into **compiled Windows executables (.exe)**.

It uses a local, **open-source AI brain** (Qwen2.5 32B via Ollama) to write Python source code, then leverages a GitHub Actions Windows runner to compile a native, downloadable application.

Every generated application is:

- **Fully autonomous** – the agent writes all code without human intervention.
- **Compiled natively** – a true Windows `.exe` built on GitHub’s `windows-latest` runner.
- **Self-contained** – no external APIs, no cloud dependencies beyond the GitHub Actions build.
- **Auditable** – every file generated by the agent is visible in the live logs.

The system demonstrates a complete AI-to-production pipeline:

```text
Prompt → ReAct Agent → Source Code → GitHub Actions → Windows .exe
```

---

## 🚀 Features

- 🧠 **ReAct Agent** – Qwen2.5 32B writes `src/main.py` and `requirements.txt` using tool calls.
- 🛡️ **Automatic Sanity Checks** – `py_compile` verification with intelligent patch rounds on failure.
- 📦 **GitHub Actions Windows Build** – Code is pushed to a dedicated repository, built on a Windows runner, and the artifact is downloaded automatically.
- 📊 **Live Logging** – WebSocket-based real-time updates stream every agent step, tool call, and build message to the frontend.
- ⚡ **One-Click Build** – Simple web UI: enter a description, click **Build EXE**, and download the resulting executable.
- 🎮 **Example Apps** – Snake game, web browsers, PDF tools, and more, all generated from short prompts.

# 🏗️ Architecture

```text
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────────┐
│  User Prompt    │────▶│  ReAct Agent    │────▶│  GitHub Actions     │
│  (Web UI)       │     │  (Ollama)       │     │  Windows Runner     │
└─────────────────┘     └─────────────────┘     └─────────────────────┘
                               │                          │
                               ▼                          ▼
                        ┌──────────────┐          ┌──────────────┐
                        │  Code +      │          │  Windows .exe│
                        │  Sanity Check│          │  Download    │
                        └──────────────┘          └──────────────┘
```

The ReAct agent writes Python source files, verifies them with `py_compile`, and pushes them to a GitHub repository.

A GitHub Actions workflow then builds the Windows executable on a Microsoft-hosted runner, and the backend downloads the resulting artifact for the user.

# ⚠️ Engineering Challenges & How They Were Solved

## ❌ Challenge 1: Cross-Platform Build Limitations

**Issue**

PyInstaller inside a Linux Docker container cannot produce a genuine Windows `.exe`.

**Solution**

The build process was offloaded to **GitHub Actions**. The agent pushes generated code to a dedicated repository, triggers a `windows-latest` workflow, and automatically downloads the resulting native Windows executable.

---

## ❌ Challenge 2: Model Tool-Calling Compatibility

**Issue**

The specialised `qwen2.5-coder:32b` model does **not** support native tool calling via Ollama, causing the agent to merely announce completion without actually creating any files.

**Solution**

Switched to the base `qwen2.5:32b` model, which fully supports Ollama tool-calling and reliably invokes `write_file` and `read_file`.

---

## ❌ Challenge 3: Silent Build Failures & Docker Cache

**Issue**

Changes to the build engine were not reflected because Docker reused cached layers. This caused the old local PyInstaller pipeline to execute instead of the GitHub Actions workflow.

**Solution**

Performed a complete rebuild using:

```bash
docker compose build --no-cache
```

Additionally:

- Used `docker cp` to overwrite files inside containers after rebuilds.
- Installed Git in the backend Docker image to enable repository operations.

---

## ❌ Challenge 4: Missing Destination Directory

**Issue**

`shutil.copy()` failed because the destination `src/` directory did not exist inside the cloned repository.

**Solution**

Created missing directories before copying:

```python
os.makedirs(os.path.dirname(dst), exist_ok=True)
```

---

## ❌ Challenge 5: Workflow Dispatch Payload

**Issue**

GitHub rejected the workflow dispatch request (`422 Unprocessable Entity`) because the required `branch` input was missing.

**Incorrect Payload**

```json
{
  "ref": "main"
}
```

**Correct Payload**

```json
{
  "ref": "main",
  "inputs": {
    "branch": "main"
  }
}
```

---

## ❌ Challenge 6: Frontend Proxy Configuration

**Issue**

The Nginx container repeatedly reverted to its default configuration, removing the `/api/` and `/ws/` proxy rules after rebuilds.

**Solution**

Mounted the custom `nginx.conf` file through `docker-compose.yml`, ensuring the configuration is always restored during startup.

# ⚠️ Limitations & Disclosure

- Windows build time depends on GitHub Actions queue length and typically completes in **2–5 minutes**.
- GitHub Actions requires a Personal Access Token (PAT) with **repo** and **workflow** permissions.
- Windows executables cannot be built locally on Linux; compilation always occurs on GitHub's Windows infrastructure.
- Generated executables are **unsigned**, so Windows SmartScreen may display a warning.
- Output quality varies because the system relies on the open-source **Qwen2.5 32B** model rather than larger proprietary models.
- All screenshots shown are from actual executions and are **not** staged or manually edited.

# ▶️ Usage

## 1. Clone the repository

```bash
git clone https://github.com/shubham-61291/magnetar-exe-builder.git
cd magnetar-exe-builder
```

---

## 2. Configure environment variables

Create a `.env` file:

```env
OLLAMA_BASE_URL=http://172.17.0.1:11434
OLLAMA_MODEL=qwen2.5:32b
GITHUB_TOKEN=ghp_your_github_token
```

---

## 3. Build and start the containers

```bash
docker compose up -d --build
```

---

## 4. Open the dashboard

Navigate to:

```text
http://<your-vm-ip>:3000
```

---

## 5. Build a Windows application

1. Enter a detailed application description.
2. Click **Build EXE**.
3. Wait approximately **2–5 minutes**.
4. Download the generated Windows executable.

Example prompt:

> Create a Snake game with arrow key controls, score display, collision detection, restart functionality, and retro styling.
